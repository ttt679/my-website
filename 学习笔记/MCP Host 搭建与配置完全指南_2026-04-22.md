# MCP Host 搭建与配置完全指南（供知识库备案）

## 一、核心概念回顾

*   **MCP（Model Context Protocol）**：一个让 AI 应用（Host）调用外部工具（Server）的标准协议，类似“AI 的 USB 接口”。
*   **Host**：你的 AI 应用（如你正在开发的 Gradio 工具），负责理解用户意图，决定调用哪个工具，并管理与 Server 的通信。
*   **Client**：Host 内部的一个模块，专门负责与单个 MCP Server 建立连接、发送请求、接收响应。
*   **Server**：提供具体功能的独立程序，如 Obsidian MCP Server（可以读写笔记、搜索、创建文件）。
*   **关系**：Host 启动 Client → Client 连接 Server → 双方通过 JSON-RPC 消息通信 → Host 调用 Server 的工具 → 获取结果返回给用户。

## 二、搭建 Host 需要准备的环境

### 2.1 基础依赖
*   Python 3.10+（推荐）
*   pip 包管理器
*   可选：Node.js（如果你的 MCP Server 是用 Node.js 写的，如 Obsidian MCP Server）

### 2.2 Python 库
*   `mcp`：MCP 官方 Python SDK，提供客户端和服务器的基础类。
*   `openai` 或 `anthropic`：用于调用 LLM 的 API（DeepSeek 兼容 OpenAI 格式）。
*   `asyncio`：Python 原生异步库，MCP 通信基于异步。

### 2.3 目标 MCP Server
你需要先有一个可用的 MCP Server。以 Obsidian MCP Server 为例：
1.  从 GitHub 克隆或下载项目（如 `obsidian-mcp-server`）。
2.  使用 `npm install` 安装依赖。
3.  构建（`npm run build`）得到入口文件（如 `dist/index.js`）。
4.  或者直接使用全局安装的版本。

## 三、Host 的核心组件与功能

### 3.1 Host 类（或模块）
它应该具备以下能力：
*   **连接管理**：能够启动一个或多个 MCP Server 子进程，并通过 STDIO 管道与之通信。
*   **工具列表获取**：在连接成功后，向 Server 发送 `list_tools` 请求，获取所有可用工具的 JSON 描述（名称、参数、说明）。
*   **工具调用**：接收“工具名 + 参数”，封装成 JSON-RPC 请求发送给 Server，并等待响应。
*   **错误处理**：处理 Server 崩溃、超时、无效参数等异常。

### 3.2 智能体循环（Agent Loop）
这是 Host 的“大脑”，流程如下：
1.  **接收用户的自然语言输入**。
2.  **决策**：将用户输入 + 可用的工具列表（从 Server 获取）一起发送给 LLM，并要求 LLM 返回一个结构化的工具调用指令（如 function calling 格式）。
3.  **执行**：如果 LLM 决定调用工具，则提取工具名和参数，调用 Host 的“工具调用”方法。
4.  **整合**：将工具返回的结果再发给 LLM，要求 LLM 基于结果生成最终的自然语言回答。
5.  **返回**：将最终回答返回给用户。

### 3.3 对话历史管理
*   需要保存多轮对话的上下文（用户消息、助手消息、工具调用请求、工具返回结果）。
*   当使用 function calling 时，需要将工具调用和工具响应作为特殊角色（`tool`）的消息追加到历史中。

## 四、通信协议详解（STDIO 模式）

### 4.1 启动 Server
Host 使用 `subprocess.Popen` 或 MCP SDK 的 `StdioServerParameters` 启动 Server 进程：
*   `command`：执行命令（如 `node`）
*   `args`：参数列表（如 `["path/to/server/index.js"]`）
*   `env`：环境变量（如 `OBSIDIAN_API_KEY=xxx`）

### 4.2 建立管道
*   Host 通过子进程的 `stdin` 和 `stdout` 发送/接收 JSON-RPC 消息。
*   每条消息以换行符 `\n` 分隔。
*   消息格式示例：
    ```json
    {"jsonrpc": "2.0", "id": 1, "method": "initialize", "params": {...}}
    ```

### 4.3 初始化流程
1.  Host 发送 `initialize` 请求，携带协议版本、客户端信息等。
2.  Server 返回 `initialized` 通知。
3.  Host 发送 `list_tools` 请求，Server 返回工具列表。
4.  之后就可以发送 `call_tool` 请求。

### 4.4 工具调用示例
*   **请求**：
    ```json
    {
      "jsonrpc": "2.0",
      "id": 2,
      "method": "tools/call",
      "params": {
        "name": "obsidian_simple_search",
        "arguments": {"query": "MCP"}
      }
    }
    ```
*   **响应**：
    ```json
    {
      "jsonrpc": "2.0",
      "id": 2,
      "result": {
        "content": [{"type": "text", "text": "搜索结果：..."}]
      }
    }
    ```

## 五、配置 Host 的关键步骤（以 Obsidian MCP Server 为例）

### 5.1 获取 Obsidian 的 API 密钥
1.  在 Obsidian 中安装并启用 **Local REST API** 插件。
2.  进入插件设置，点击“Generate new API key”，复制生成的密钥。

### 5.2 确认 MCP Server 的启动命令
*   如果你通过源码构建，入口文件通常是 `dist/index.js`。
*   启动命令：`node /完整路径/obsidian-mcp-server/dist/index.js`
*   环境变量：需要设置 `OBSIDIAN_API_KEY` 为上一步获取的密钥。

### 5.3 在 Host 代码中配置 Server 参数
1.  创建 `StdioServerParameters` 对象，填入 `command`、`args`、`env`。
2.  使用 `stdio_client` 上下文管理器建立连接。

### 5.4 测试连接
在 Host 中调用 `list_tools`，如果能返回工具列表（如 `obsidian_simple_search`, `obsidian_get_file_contents` 等），说明成功。

### 5.5 集成到智能体循环
1.  将工具列表转换为 **OpenAI function calling 格式**（每个工具对应一个 `function` 对象）。
2.  在调用 LLM 时传入 `tools` 参数。

## 六、常见问题与踩坑记录

### 6.1 连接失败：Server 没有启动
*   检查路径是否正确，尤其是 Windows 下的反斜杠需要转义或使用正斜杠。
*   手动在终端运行启动命令，看是否有报错（如缺失依赖、端口冲突）。

### 6.2 API Key 无效
*   确认 Obsidian Local REST API 插件已启用且密钥正确。
*   确认环境变量名称与 Server 期望的一致（常见为 `OBSIDIAN_API_KEY` 或 `API_KEY`）。

### 6.3 工具调用超时
*   某些工具（如全局搜索）可能较慢，适当增加超时时间。
*   检查 Obsidian 是否打开了需要操作的知识库。

### 6.4 LLM 返回的 tool_calls 格式不正确
*   确认你使用的模型支持 function calling（DeepSeek 支持）。
*   在请求中明确要求模型输出 JSON 格式，或使用 `response_format={"type": "json_object"}`。
