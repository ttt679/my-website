
## 战略定位
- 不是单一学习产品，而是**第二大脑（结构化知识库）+ 对话式知识生产 + 标准化互联（MCP/API）** 的开放架构。
- 核心价值：让用户与 AI 的每次对话都沉淀为可检索、可复用、可被 AI 调用的知识资产。

## 技术决策
### 1. 知识结构化程度
- **从 A（语义文档型）起步，为 B（原子化卡片型）留接口**。
  - A：Markdown 文档 + 向量检索（RAG）。
  - B：未来可拆解为独立知识卡片，支持双向链接和细粒度重组。

### 2. 检索触发模式
- **混合模式**：
  - 自动模式（默认）：每次用户输入时静默检索第二大脑，注入相关上下文。
  - 主动模式：用户用 `/brain use <库名>` 显式指定知识库，检索结果中的跨库链接会提示用户是否一并启用。

### 3. 关联元数据管理
- 利用 Obsidian 的双向链接（`[[笔记名]]`）和反向链接功能，通过定期扫描生成链接索引 JSON，实现跨库关联提示。

## 分阶段执行规划

### Phase 1：最小闭环验证（2 周）
**目标**：对话 → 保存 → 检索 → 再对话。

#### 任务
1. **增加向量数据库**：Chroma（嵌入式）。
2. **嵌入模型**：OpenAI `text-embedding-3-small`。
3. **自动检索注入**：
   - 在 `/chat` 接口中，对用户输入做向量检索（top-5，相似度阈值 0.7）。
   - 结果拼接到 system message，并限制总 token ≤ 2000（超则压缩或截断）。
4. **主动模式命令**：
   - 支持 `/brain use "库名"`、`/brain list`。
   - 知识库注册表：JSON 文件，每个库对应 Obsidian 文件夹路径或标签筛选。
   - 解析检索结果中的 `[[...]]` 链接，查询预先生成的链接索引，若目标库未启用则弹出提示。
5. **UI 调整（Gradio）**：
   - 开关：「🧠 自动检索」
   - 按钮：「🔍 手动检索」+ 输入框
   - 展示检索到的知识块（可折叠）

#### 验收标准
- 用户问“我上次关于 X 说过什么？”AI 能正确引用。
- `/brain use Python笔记` 后只从该文件夹检索。
- 跨库链接提示功能正常。

### Phase 2：标准化接入与知识卡片化（1 个月）
**目标**：工具可被其他 AI 调用，Markdown 可升级为卡片。

#### 任务
1. **发布 MCP Server**：
   - 实现 `resources/list`、`resources/read`、`tools/search`。
   - 用 FastAPI + SSE 包装。
2. **提供 API 文档**（Swagger）：`/search`、`/save`、`/libraries`。
3. **知识卡片拆解**（可选）：
   - 后台 LLM 将新文档拆为卡片，存储为独立 `.md` 或 JSON。
   - 卡片与原文双向链接。
4. **增强跨库关联**：
   - 主动模式中，若卡片包含 `[[other_library/note]]`，自动提示添加库。

#### 验收标准
- 外部 AI 通过 MCP 能搜索到笔记。
- 用户可手动触发“拆解为卡片”。
- 跨库关联提示覆盖卡片链接。

### Phase 3：人+AI 协作工作流（2 个月）
**目标**：对话即生产，支持知识冲突与演化。

#### 任务
1. **增量更新**：修改笔记时自动更新向量库和卡片索引。
2. **知识冲突检测**：新内容与旧知识矛盾时提示用户选择保留/合并/标记演化。
3. **版本演化**：同一主题的时间线视图（类似 Git 历史）。
4. **主动推荐**：根据当前对话推荐相关但未被召回的笔记。
5. **导出与分享**：导出为 Anki 牌组、PDF、JSON 知识图谱。

## 技术选型表

| 组件           | 推荐方案                          | 备注                     |
| -------------- | --------------------------------- | ------------------------ |
| 向量数据库     | Chroma (Phase 1) → Qdrant (可选)  | 轻量起步                 |
| 嵌入模型       | OpenAI text-embedding-3-small     | 成本低，效果好           |
| 卡片拆解 LLM   | 现有 DeepSeek API                 | few-shot prompt          |
| MCP SDK        | `mcp` (PyPI) 或自建 FastAPI+SSE   | 官方 SDK 更规范          |
| 链接索引       | 自定义 Python 脚本扫描 Obsidian   | 正则提取 `[[...]]`       |
| 前端           | Gradio + 少量 JS                  | 保持轻量                 |

## 风险与对策

| 风险                   | 对策                                                         |
| ---------------------- | ------------------------------------------------------------ |
| 自动检索污染对话       | 相似度阈值 0.7 + UI 开关 + 显示召回了什么                    |
| 上下文超长             | 限制注入 token ≤2000，支持压缩/重排                          |
| MCP 标准变化快         | 只实现稳定的核心 resources/tools                             |
| 用户不知如何使用主动模式 | 聊天输入框上方提示 `/help`，提供可视化库选择器               |
